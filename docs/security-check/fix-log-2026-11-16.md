- `server.ts:4455-4480`: listens on 127.0.0.1, plus a second listener on ::1 sharing the same request

- `app/src/rate-limit.ts`: `isLoopbackSocket`, `clientAddress` reads the cf header only on a loopback

- Red to green: f1, f3, f6 (f2, f4, f5 stay green). Added f7 and f8.

## A2, Claude spend limits and loud monthly cap

- `server.ts:1560-1670` (`claudeAskRefusal`): each Claude ask must pass a per-device limit (12 per 10
  minutes, 40 per day, not counted for a caller on this machine), the weekly allowance for the device
  (free or Plus limit, so typing names cannot get past it), a per-network limit (/24 or /64: 100 per 10
  minutes, 250 per day), then the existing per-address bucket. The shared "open" code bucket no longer
  counts Claude asks (`paidCallRefusal(req, false)`), so one caller cannot empty it for everybody.
- Monthly cap reached: `noteClaudeCapIfReached` counts a customer-data fault
  (`claude_monthly_cap_reached`, `app/src/customer-data-faults.ts`), writes an errlog line (at most once an
  hour) and `/api/health` carries `claudeMonthlyCap {reached, refusedAsks, since}`. The server already
  stopped calling Claude at the cap; now it says so.
- Red to green: d2, d5, d6, b9 (d1, d3, d4, d7 stay green).

## A4, device claims, demo route, scan probing

- `app/src/device-key.ts` `ownsDevice`: an unbound id is no longer claimable by a request that names a
  different device in its header, or that carries a key with no matching header.
- `/api/quota` (`server.ts:2921`) takes proof of the device (bound secret), since it carries the Plus answer.
- `/api/identify/demo` refuses a device the caller does not own before it records anything.
- `/api/scan/:id/outcome` (`server.ts:2929`): a missing scan and someone else's scan both answer 403.
- Red to green: a10, a11, a12, b5 (with b3, see A3).
- Left open: the legacy window is narrowed, not closed. A caller that sends no device header and no key
  at all, and knows an unbound id, is still treated as that device on routes other than quota and Plus
  (ids are random per phone and unlisted). It closes as old phones bind. Closing it now would strand
  testers whose phones have an id and no key. Tests changed for the new rules: server-quota.test.ts and
  plus-scan-cap.test.ts (quota calls carry the device key), the outcome test now expects 403 for a missing scan.

## A5, wrong guesses at the admin token and the invite code

## A7, input limits

- A typed name longer than 160 characters is not sent to Claude (`server.ts:1572`).
- RevenueCat is asked only about a device that proves its secret and whose id matches
  `^[A-Za-z0-9_-]{8,64}$` (so dot and slash ids are never sent), with a global ceiling of 120 uncached
  lookups a minute and a warning when it bites (`app/src/scan-quota.ts`, `isPlus`). The RevenueCat test in
  server-quota.test.ts now uses a keyed device with a real-shaped id.
- `/api/stores`: 30 lookups per 10 minutes and 300 a day per address (`server.ts:4139`), not counted for
  a local caller.
- Headers added next to the CSP: `X-Content-Type-Options: nosniff`, `Referrer-Policy:
  strict-origin-when-cross-origin` (`server.ts:2520`).
- Red to green: b7, b8, i5, d8.

## A3, free scans per minted id

Not fully fixed, left for a product decision. b3 (a stranger naming someone else's id) is green through
the A4 change. What remains is the real hole: a phone can mint a new id with a new key for every scan and
get a fresh free allowance each time. The only brake today is the per-address free-scan cap
(`SHIN_FREE_SCANS_PER_IP_DAY`, default 30, on only while the free limit is on). A per-address cap on new
device ids was not added because shared carrier and campus addresses would lock out honest new installs.
Options: (1) a per-network cap on new ids per week, (2) Apple App Attest or DeviceCheck so one phone cannot
mint many ids, (3) accept the cost, since the free scan is a catalogue lookup and Claude asks are now bounded.
No security test is left red for this.
