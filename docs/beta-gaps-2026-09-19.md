# What is not ready for beta, against Jamin's walkthrough notes (2026-09-19)

Checked against the CODE (not plan docs) by two read-only audits on 2026-09-19, at commit after
cd79c4c. Requirements: `docs/walkthrough/jamin-notes-2026-09-17.md` and the "Walkthrough rulings"
section of `docs/jamin-gemini-rules.md`. File:line citations are the audits'; not every line was
re-verified by hand. Saved at his word: *"save this as a list"*.

## Blockers: the scan path contradicts his rules

1. Photo identification runs on Claude. `model.ts:854-864` defaults to AnthropicProvider unless
   `SHIN_MODEL_PROVIDER=gemini`, which is unset; `server.ts:946`, `identify.ts:190`.
2. Shin's own catalogue answers first; Gemini only on a miss. `server.ts:1321` photoLookup,
   `identify.ts:158-166`, `server.ts:2121`.
3. Shin runs the price math locally and shows it. `gauge.ts:622` computeGauge after
   `gemini-grounded.ts:434-441`.
4. No `gemini-2.5-flash` anywhere; defaults are `gemini-3.5-flash-lite` / `gemini-3.8-flash`
   (`identify/src/providers/gemini.ts:141-146`). No live per-scan two-model path for the beta
   (only the offline matrix in `eval/run.ts:87-161`).
5. Response schema is sent with `google_search` (`gemini-grounded.ts:438,441`), which only Gemini
   3 supports. `parseJson` repair exists (`565-586`) but throws ProviderError on failure
   (`604,700-701`), so a bad answer can fail the scan.
6. User good/bad/great thresholds are stored (`setup.js:147`, `you.js:539`, `store.js:46-47`) but
   never sent in any `api.js` request; boundaries come from the server (`price-line.js:331-332`).

## Barcode and camera

7. Barcodes are not read until the button is pressed: `app/src/eye/camera.ts:362` gates decode on
   `#barcodeWanted` (default false); one-shot and disarms on first hit (`camera.ts:367`,
   `barcode.ts:238`). The button is always rendered (`camera.js:2087`) instead of appearing after
   the vote. The vote and window logic itself exists (`barcode.ts:112-113,215,229-231,259`;
   window 900 ms, spec says 1 to 2 s).
8. Only the largest barcode is kept (`barcode.ts:222-224`): no highlight of every barcode, no
   distinct focused one.
9. No "centre it" coaching: `framing.ts:62,133` has hold/glare/closer/pick only.
10. Shelf price is asked after identification (`camera.js:3450,3493,3255-3272`), not at scan time.
11. Torch is a manual toggle (`camera.js:2655,3792`): no brightness slider, no too-dark prompt.

## Recording

12. Every Gemini request and response is not stored; `server.ts:2321-2341` keeps a derived summary
    only.
13. Photo saved only with consent (`scans.ts:317`); the user's verdict rating keeps only the
    latest (`ratings.ts:91-102`).
14. No hidden check of Gemini's math and no mismatch marking (`gemini-grounded.ts:445-457`).
15. Unknown products are logged for human review (`gaps.ts:38-50`), never created in the catalogue.
16. No continuous shelf-crop capture: `/api/shutter/frame` is one frame per press
    (`server.ts:1892-1903`), cropped to the focused item (`camera.ts:545`, `detector.ts:290`).

## Features

17. Onboarding: 2 of the 33 Welcome screens exist (the threshold picker `setup` and `consent`;
    `main.js:36-49`). No shop-type, frequency, priority, charts, paywall, sign-in or setup screens;
    `market.js:57-158` is a Settings country picker, shops are inferred (`shops.js:1-40`),
    location is a permission toggle only (`consent.js:69-76`).
18. Alternatives: one undifferentiated path (`catalogue/src/alternatives.ts:630`), no validation
    vs alternatives modes, no organic/farm/used/bulk constraints.
19. Canada still hardcoded: `alternatives.ts:559,591` filters `sold_in_canada=1`; `spine.ts:664+`
    CAD text; `gauge.ts:222` defaults to CAD.
20. Unit conversion wrong for kg and l in `alternatives.ts:273-276,696` (the verdict's own
    `verdict.ts:175-192` is correct).
21. Offline mode still resolves barcodes (`app/public/js/offline-aisle.js:48-66,81-83`), against
    *"For now, the app will not be usable offline."*

## Already in line with his notes

- Native app, not browser (`native/capacitor.config.json`, android and ios projects).
- Low-confidence answers shown with a mark rather than refused (`identify/src/confidence.ts:127-141`).
- Guard failures degrade instead of crashing (`server.ts:1753-1769,2123-2135`).
- Barcode scans send digits only, no image (`api.js:279-296`, `gemini-grounded.ts:435`).
- Threshold range screen (`setup.js:92-108`).
- Typed price, location and store recorded (`scans.ts:277-324`); units normalised with originals
  kept in the verdict path (`schema.ts:46-48,106-108`).
