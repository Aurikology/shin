# Defects

One row per defect. **The only interesting column is whether a test caught it or a human did.**
Everything else here is bookkeeping; that column is the measurement.

## The two rules that govern this file

1. **A defect logged twice becomes a build standard. Once is a bug fix.** One occurrence gets
   fixed and gets a row. A second occurrence of the same shape earns a rule, and the rule goes in
   the standards section at the bottom of this file. Nothing else in this repo generates new
   rules. The alternative was measured in another repo: twenty-eight standing instructions in
   twenty-two days, most of them backed by nothing.
2. **This file is read at the start of every pass, right after the scoreboard,** and it is
   allowed to reorder the queue. See step 1 of `PASS.md`.

## The check that says whether any of this is working

Three passes in, if `SCOREBOARD.md` has no series and the "caught by" column below is all
humans, the loop is decoration and every mechanism failed at once. Two columns, one minute.

## Build standards earned by a repeat

**1. A price is never compared against the seller quoting it, and every caller carries the seller
to make that possible.** Earned by D-003 and D-009. D-003 was the engine including the judged
store in its own comparison set; D-009 was a caller omitting `askingSeller` so the engine could
not exclude anything. Same wrongness, opposite ends of the same call, and the second one survived
the test written for the first because that test called the engine directly.

Forbidden: calling `priceIt` for a price observed somewhere without passing where it was observed.
Required: any stored record of an observed price stores its seller alongside it, and any code that
normalises or copies such a record carries the seller through. The literal string `given`, which
the spine uses when no store was named, is not a seller and must never be stored as one.

The wider lesson, and the reason this is a standard rather than a third bug fix: **a test that
locks a fix at one layer does not lock the fix.** D-003's test asserts the engine excludes the
judged seller. It passes. The app was still comparing Kraft Dinner to Kraft Dinner, because the
question was never asked with the seller in it.

**2. A piece is not built until something a person can reach calls it, and the check that says it
is built has to run through that path.** Earned by D-023 and D-024, with D-025 and D-026 as four
further instances found the same hour. D-023 is the offline aisle: the server serves the slice, the
phone module parses and stores it, the endpoint test passes, and no screen imports the module, so
the aisle does not work. D-024 is the identification chain and the vision read, complete and tested
and imported by nothing while the camera shows a hand-written list.

Forbidden: recording a piece as built on a test that calls it directly, or on an endpoint answered
by hand. Required: the check names the path a person takes and runs it end to end. A new file
lands with its caller in the same change, or it lands with a row here.

This is standing instruction 08-06 arriving from inside the product rather than from a document,
and the cost of not having it is measured: eight finished, tested pieces sitting unreachable at
once, which reads as a working product in a test run and as an empty one in a browser.

**3. Every pass ends with somebody looking at the running screens.** Earned by the caught-by
column and not by an argument: twenty-eight of the thirty-seven defects here were found by looking
at a rendered screen or by asking who calls a piece of code, and one was found by a test. D-004 was a
sentence that read wrong while every test asserting the tier passed. D-021 is the same shape one
layer up, a function that will ship "Saved at undefined" and return it silently.

**D-033 is the sharpest version of it so far, and it is worth reading before trusting any suite in
this repo: the test written for exactly that property was green at the moment the screen was
wrong.** A palette pass computed every text-on-tier pairing in both themes and passed, while seven
rules on the verdict surface faded that same text below the same floor, because the test modelled
the one opacity anybody remembered and the stylesheet used five. A test covers the model it was
given, and the screen is not obliged to be that model.

Forbidden: closing a pass on a green test run alone. Required: the screens are walked, in both
themes, and what was walked is written down. This is a habit and gets no hook.

**4. A claim about a value is computed from the declaration, never read from prose near it.**
Earned by D-085 and by the AVATAR.md row 46 correction on the same day. D-085 is a lane reporting
`--ink-faint` as failing contrast on every ground, changing two lines on the strength of it and
filing a third as a defect, having read the numbers out of a `tokens.css` comment that exists
specifically to record that those numbers are OBSOLETE and what replaced them. Row 46 is the
mirror image at the same hour: `AVATAR.md` said the Recently removed header draws a 28px face, the
code has always drawn 48, and a comment in `removed.js` cited the row as its authority for a size
the row does not give. In both cases the writing near the thing was trusted over the thing, and in
both cases the writing was the older of the two.

Forbidden: asserting a colour, size, duration or threshold from a comment, a doc table or a commit
message. Required: resolve it from the declaration the machine reads, and when the two disagree,
the declaration wins and the prose gets fixed in the same edit. `app/test/tokens.test.mjs` parses
`tokens.css` rather than describing it and is the pattern to copy; a lane making a colour claim
copies its parsing, not just its arithmetic.

The wider lesson: **this repo's comments are unusually long and unusually good, which is exactly
what makes them dangerous.** A comment that carefully records why a value was wrong reads, three
days later, like a record of a value that is wrong.

When one is earned, write it as one sentence naming the shape, the two occurrences that earned
it, and what it forbids.

**5. A backup is verified against the hosts, never read out of a file, and the file says which
machine it is describing.** Earned by D-088 and by the 2026-09-07 correction it repeats. Both
times `CLAUDE.md` described a push configuration that was not the one in `git config`; both times
the description was plausible, recently written, and wrong; and both times a push kept succeeding
and printing a normal ref update while reaching fewer hosts than the file claimed. The second
occurrence had run for six days and left the mirror 25 commits behind.

Forbidden: reporting a repository as mirrored, backed up or in sync on the strength of a remote
being listed, a CI badge being green, a provider page saying "last update succeeded", or this
file saying so. Required: `git ls-remote <remote> refs/heads/<branch>` against BOTH hosts,
returning the same SHA, run AFTER the push that matters. A rotated token, a deleted repository
and a missing `pushurl` are all invisible to every other signal and identical to success.

The second half is the one this repo keeps relearning: **a remote configuration is a property of
a clone, not of the project.** Two people working one repo do not have the same remotes, so a
sentence in a shared file that says "one push writes both hosts" is true on somebody's machine
and false on somebody else's, and it is false for whoever reads it last. Any claim about remotes
names the machine it was measured on and the date it was measured.

**6. A language is looked up where the reader is, never baked in where the thing is made.**
Earned by D-092 and D-093 on the same day. D-092 localised the face label where the face is DRAWN
and left the path that CHANGES it writing hardcoded English, so a French screen reader was correct
until Shin moved and wrong on every verdict after. D-093 was the same sentence frozen into 39
build artifacts that have no runtime in which to look anything up. Both shipped inside the pass
that added French, both passed every check, and in both the markup was right somewhere and the
product wrong somewhere else.

Forbidden: a user-facing string written as a literal at the point where markup is produced,
mutated, or generated -- including in a build script, a static asset, or an in-place
`setAttribute`. Required: the producer emits an IDENTIFIER and the facts; the layer that knows who
is reading chooses the words. `spine` already does this for a verdict (a line code plus raw facts,
never a finished sentence) and `voice.js` for everything Shin says; assets and update paths are
held to the same rule.

The test that actually catches this is not "the label is right". It is **the render path and the
update path AGREE**, and for a generated file, **the bytes on disk** rather than the module that
wrote them -- a pairwise comparison of generator to output cannot tell correct apart from
consistently wrong, which is exactly how 39 files stayed wrong through a green suite.

**7. A gate is an exit code, never a printed tally.** Earned by D-105, the same failure twice in one
day: a push chain that ran the checks, echoed the numbers and pushed regardless, once past a red
test and once past a red typecheck. The rule: whatever decides a push (or a deploy, or a merge)
runs on the COMMITTED tree, includes every package the merge brought in as well as every package
the local diff touched, and stops on the first nonzero exit before the push command can start;
the tally is for the human reading the log afterwards, not for the machine deciding. On this
machine that is `~/bin/shin-gate.sh`; a session that pushes without it is doing the thing this
standard exists to stop.

**8. Slow and dead are different states, and a check that cannot tell them apart must not act as
if it can.** Earned by D-127 and D-128, the same shape twice on 2026-09-19. D-127 was a test's
`alive()`: one fetch, a 2,000 ms timeout, `catch { return false }`, so a busy laptop read as a dead
server and four tests reported a death that never happened. D-128 was the barcode reader: one
decode past a 1,500 ms ceiling latched `#wedged` forever, so one slow frame on a cold phone ended
scanning for the visit.

Forbidden: a timeout whose expiry is treated as proof of the failure it was watching for, when a
slower version of success would look identical. Raising the number is not the fix; it moves the
false reading to a busier machine.

Required: name the evidence that actually separates the two, and use it. A process that is gone
REFUSES a connection, at once and every time, while a busy one answers late -- so a refusal is
death and a timeout is a retry inside a budget. A dead WebAssembly module never settles AT ALL,
while a slow one settles late -- so the outstanding promise is watched rather than abandoned, and
its late arrival is proof of life. Where no such evidence exists, require repetition before acting,
and write down what the repetition count is buying.

The wider lesson: **a check that fails when the machine is busy is worse than no check.** It
teaches everyone to read red as noise, and the next real failure reads exactly like the false one.

**9. A pre-load, a warm-up or any other optimisation must not be able to kill the thing it was
speeding up.** Earned by the 2026-09-08 malformed-`Host` death and D-129, which is the same
unhandled rejection in a second place. There, `new URL` threw outside the try that answers
everything else; here, a `warm` job missed a 5,000 ms deadline and rejected a promise **nothing in
the repo awaits**. Node 24 exits on an unhandled rejection, so both ended with the server gone for
everybody -- and D-129's died waiting for an embedder it had already reported as switched off.

Forbidden: creating a promise at boot that nothing consumes, and any optimisation path whose
failure is not explicitly caught and demoted.

Required: an optimisation's failure degrades and says so on stderr. If a promise has no consumer,
it has no business being able to end the process; give it a `catch` at the point it is created,
not at some caller that does not exist.

There is also a net, added 2026-09-19 with this standard: `app/server.ts` registers an
`unhandledRejection` handler that logs through `logError` and keeps serving. It is an admission
that there will be a third instance, not a licence to skip the two rules above -- every rejection
reaching it is still a defect to find and fix at its source. `uncaughtException` is deliberately
NOT caught beside it: a rejected promise is a value, an escaped throw is a wrecked stack, and
serving on from the second is how a crash becomes corrupt data. `app/test/process-net.test.mjs`
guards all three of those choices at the source, and says in its own header that it is a source
check and not a behaviour one.
