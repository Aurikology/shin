# OpenAdaptAI/openadapt-ml

One line: a research library that shows a vision model one screenshot plus a text list of labeled UI elements and asks it, in plain prompt text, to return JSON naming which element to click; every model call is single shot, prompt only, with no API level schema, no tool or search config, and no retry.

Read depth: opened `openadapt_ml/grounding/{base,detector}.py`, `openadapt_ml/models/providers/{google,anthropic,openai,base}.py`, `openadapt_ml/models/api_adapter.py`, `openadapt_ml/models/qwen_vl.py`, `openadapt_ml/baselines/{prompts,parser,adapter,config}.py`, `openadapt_ml/runtime/{policy,safety_gate}.py`, `openadapt_ml/evals/grounding.py`, `openadapt_ml/perception/integration.py`, `openadapt_ml/segmentation/{frame_describer,schemas,cache,deduplicator}.py`, `openadapt_ml/schema/episode.py`, `openadapt_ml/training/grpo/{config,reward,rollout_collector,rollout_env}.py`, `examples/test_gemini_grounding.py`, `pyproject.toml`, plus greps across `openadapt_ml/`, `scripts/`, `examples/`, `tests/`. Deliberately not read as evidence: the 140 file `docs/` tree (planning documents, several of which describe Gemini grounding features the source does not contain), `deprecated/`, CI workflows, `experiments/*/eval/*.json` result dumps, and the training/viewer UI code (`openadapt_ml/training/{viewer,benchmark_viewer,shared_ui}.py`). Clone at HEAD `8811400`, 2026-09-02.

## Q1 image plus search

- The only live image-to-model grounding call is one Gemini call with the image and a text prompt in a plain Python list, no tools, no grounding config: `openadapt_ml/grounding/detector.py:237` sends `model.generate_content([prompt, image], generation_config=genai.GenerationConfig(temperature=0.1, max_output_tokens=1024))`. Model id defaults to `"gemini-2.5-flash"` (`detector.py:47`), SDK pin `google-generativeai>=0.8.5` (`pyproject.toml:27`). For a grocery photo this is the whole mechanism: one shot, one image, whatever the model knows already, nothing retrieved.
- The prompt hands the model the pixel dimensions and demands pixel coordinates back, which is the closest thing here to a resolution hint: `detector.py:216` `"The image is {image.width} pixels wide and {image.height} pixels tall."` and `detector.py:224` `"IMPORTANT: Use exact pixel coordinates based on the image dimensions provided above."`. No cropping or resizing happens on the API path; the only resolution control in the repo is `max_pixels`/`min_pixels` on the local Qwen processor (`openadapt_ml/models/qwen_vl.py:100-144`), which never leaves the machine.
- The shape of the answer is requested in prose, not enforced: `detector.py:219-229` asks for a JSON array of `{"bbox": [x1,y1,x2,y2], "confidence": float, "label": ..., "text": ...}`, gives one example row, and ends `"Return ONLY the JSON array, no other text."`. Relevant to a price app because the same trick (ask for JSON, hope) is what fails intermittently under load.
- Candidates are described to the model as a numbered text list, not as drawn marks, on the other live path: `openadapt_ml/baselines/prompts.py:549-550` appends the raw unmodified screenshot via `encode_image_fn`, and `prompts.py:579` heads the accessibility tree with `"## UI ELEMENTS"` when set-of-marks mode is on, `"## ACCESSIBILITY TREE"` otherwise. Each node is rendered at `prompts.py:648-670` as `[{node_id}] {role}: "{name}" @ ({cx:.2f}, {cy:.2f})`. This is directly the Shin shape: image plus a labeled candidate list in text, model picks a label.
- The pick is turned back into a concrete choice as an integer index, not coordinates, when an id is available: the Track C system prompt (`prompts.py:182-241`) says `"UI elements in the screenshot are labeled with numbered markers like [1], [2], [3]"` and closes with `"element_id must be an integer from the labeled elements"`; the parser prefers that id over any coordinates, `openadapt_ml/baselines/parser.py:496-499` `element_id = data.get("element_id", data.get("ControlLabel"))` checked before `x`/`y`; `ElementRegistry.resolve_coordinates` (`parser.py:82-93`) then maps the id back to a bbox center. An index into a candidate list is exactly how a photo should be matched to a price row.
- Per provider image attachment, all base64 or raw PIL, all inline in the same single request: Anthropic `openadapt_ml/models/providers/anthropic.py:208-213` builds `{"type":"image","source":{"type":"base64","media_type":"image/png","data": self.image_to_base64(image,"PNG")}}` sent at `anthropic.py:150-156`; OpenAI `openadapt_ml/models/providers/openai.py:187-212` builds a `data:image/png;base64,...` image_url; Google `openadapt_ml/models/providers/google.py:209-228` passes the PIL object straight through. Temperature defaults to 0.1 on all three (`anthropic.py:128`, `openai.py:128`, `google.py:135`).
- Search and image never share a request, because nothing in the repo ever sends a search tool at all. `grep -rn "google_search\|googleSearch\|grounding_config\|GoogleSearch\|search_retrieval\|vertexai" openadapt_ml/ --include=*.py` returns zero hits. The word "grounding" throughout this repo means visual localization of a UI element, not retrieval grounding. There is therefore no two-call pattern, no hand-off object, and nothing deciding a second call happens.

## Q2 stopping being wrong

- The one calibration mechanism that is real and wired: an empty candidate list means "looked and matched nothing", an unreadable reply raises instead of faking a miss. `openadapt_ml/grounding/base.py:20-29` documents it, and `openadapt_ml/grounding/detector.py:118-123` enforces it: if the regex finds no JSON, it raises `GroundingError("Gemini response contained no JSON array or object; the model reply could not be read at all...")` rather than returning `[]`. For Shin this is the difference between "no price found for this item" and "the price lookup crashed", which are scored identically by most naive pipelines.
- The evaluator refuses to silently shrink its own denominator: `openadapt_ml/evals/grounding.py:257-266` replaces a former `except Exception: continue` with a raised `ValueError` when a screenshot cannot be opened, with the comment that a hit rate computed over fewer samples "stayed high and nothing said it was computed over fewer samples than the episode contains". Directly transferable to measuring a photo-to-price hit rate honestly.
- A confidence gate with an enum band exists and is genuinely written, but is not connected (see Dead or unwired): `openadapt_ml/runtime/safety_gate.py:396` `if confidence is not None and confidence < self.config.confidence_threshold:` returns `SafetyDecision.REQUIRE_CONFIRMATION`; default threshold `0.7` at `safety_gate.py:142`; the band is `ALLOW / BLOCK / REQUIRE_CONFIRMATION` at `safety_gate.py:45-50`. A loop cap sits beside it: `safety_gate.py:307` blocks when a state has been visited `loop_threshold` times, default `3` (`safety_gate.py:143`).
- Missing confidence is invented, not flagged: `detector.py:168-169` `confidence = item.get("confidence", 0.8)`. A model that omits the field gets scored as 80 percent sure. That is the failure mode a price app must not copy.
- No retry anywhere near a model call. `grep -rn "retry\|max_retries\|backoff\|@retry" --include=*.py` outside `tests/` hits only cloud provisioning (`openadapt_ml/cloud/lambda_labs.py:501,629,676,1405,1480`, `openadapt_ml/cloud/vast_ai.py:386,466,1077,1101`), which repeat an identical SSH or rsync call after a sleep. No `tenacity` or `backoff` import exists. Providers classify an exception into `RateLimitError`/`ProviderError` and re-raise; no caller catches them.
- No cross-source reconciliation. The place it would live is a stub: `openadapt_ml/perception/integration.py:310-311` `# TODO: Implement deduplication by IoU if threshold provided` / `# For now, just combine all elements`, so two detectors disagreeing produces a concatenated list with no tie-break. The real threshold in the repo, `WorkflowDeduplicator` cosine similarity `>= 0.85` (`openadapt_ml/segmentation/deduplicator.py:443`), dedupes training episodes, not competing answers.

## Q3 same shape every time

- One real determinism mechanism, and it is a content-addressed response cache: `openadapt_ml/segmentation/frame_describer.py:493-502` keys on `hashlib.md5(png_bytes).hexdigest()[:12]` plus `hashlib.md5(json.dumps(action, sort_keys=True).encode()).hexdigest()[:8]`; `_load_cached`/`_save_cached` at `:504-526` read and write one JSON file per key; wired live at `:569-570` (lookup before the call) and `:601-602` (store after), on by default (`cache_enabled: bool = True`, `:409`). Same photo plus same context returns the identical description with no second API call. This is the single most portable idea here for making a photo path replayable.
- Temperature is pinned low everywhere on the inference paths, though never to 0: `0.1` at `detector.py:240` and `detector.py:365`, and as the default of every provider `send_message` (`anthropic.py:128`, `openai.py:128`, `google.py:135`). Contrast `openadapt_ml/training/grpo/config.py:67` `temperature: float = 0.7`, deliberately raised for rollout diversity during RL training.
- Typed local schemas exist, with a real enum and required fields, but they describe captured data, not model output: `openadapt_ml/segmentation/schemas.py:19-29` `class ActionType(str, Enum)` with eight fixed values, used as a required field at `schemas.py:54` `action_type: ActionType = Field(...)`; nullable siblings at `schemas.py:56-63`. `openadapt_ml/schema/episode.py:182-184` has a genuine `Optional[Literal["up","down","left","right"]]`, and `episode.py:229-244` a `@model_validator(mode="after")` that raises when a TYPE action has no text.
- Nothing is enforced at the API level. `grep -rn "response_schema\|response_mime_type\|response_format\|json_schema"` finds only `Episode.model_json_schema()` (`openadapt_ml/schema/episode.py:394-396`), a local introspection helper never passed to a model call. Every provider call carries only `temperature` and a token cap.
- No validator re-asks. A parse failure degrades silently to a hardcoded stub: `openadapt_ml/segmentation/frame_describer.py:103-113`, `except json.JSONDecodeError: pass` then `return {"apparent_intent": text, "confidence": 0.5}`. Zero retries, and the invented 0.5 confidence then flows onward as if measured.
- Prompts are inline Python strings, not template files: no `.jinja`, no runtime-loaded prompt file, no `jinja2` import anywhere in `openadapt_ml/`; all assembly is f-strings and concatenation (`openadapt_ml/baselines/prompts.py`, 787 lines of `_format_*` methods; `detector.py:214-229`). One optional single demo example can be spliced in at `prompts.py:465-477` ("Here is an example of successfully completing a similar task:"), which is one-shot conditioning, not a fixed few-shot bank.
- No seed reaches a model. `random.seed` appears only in synthetic data generation and experiment sharding (`openadapt_ml/ingest/synthetic.py:1188-1189`, `openadapt_ml/experiments/representation_shootout/runner.py:188,263-264`); no `seed=` parameter is passed to any Gemini, Anthropic, or OpenAI call.

## Nothing here on

- Search, retrieval, or web grounding of any kind. Searched `google_search`, `googleSearch`, `google_search_retrieval`, `grounding_config`, `GoogleSearch`, `search_retrieval`, `vertexai`, `web_search`, `tools=` across `openadapt_ml/` and `scripts/`; the only `tools=` hit is dead code (below).
- Citation or grounding metadata verification. `grep -rn "grounding_metadata"` and `grep -rni "citation"` over all `.py` files return zero matches, so nothing reads, checks, or drops an unsupported claim.
- Anything price shaped. Searched `price`, `currency`, `usd`, `\$[0-9]`, `stale`; every hit is GPU billing for training runs (`openadapt_ml/cloud/lambda_labs.py:1354` `INSTANCE_PRICES`, `openadapt_ml/cloud/local.py` `cost_usd`/`hourly_rate_usd`). No number is ever extracted from an image or page, and no currency, unit, date, or staleness check exists.
- Replay of recorded model outputs. Despite the project family name, no code loads a prior run's saved model responses to stand in for a live call; the frame-describer cache above is same-input memoization, not run replay. Searched `replay`, `record`, `determinis` across `openadapt_ml/` and `scripts/`.
- A thinking budget. `thinking_budget` is declared at `openadapt_ml/baselines/config.py:110` and never read by any provider or adapter.

## Dead or unwired

- `SafetyGate`, the entire confidence-gate plus loop-cap machinery (`openadapt_ml/runtime/safety_gate.py`), has no production caller. `grep -rn "SafetyGate(\|\.assess(" --include=*.py .` returns five hits, all inside docstrings: `safety_gate.py:12,20,23` and `openadapt_ml/runtime/__init__.py:13,17`. No test file references it. Worse, the field it reads, `action.raw["confidence"]` (`safety_gate.py:274-281`), is never populated by anything that builds an `Action`.

- `send_with_grounding` (`openadapt_ml/models/providers/google.py:300-377`) is named for search grounding but is a plain `generate_content([prompt, image], ...)` with no tool config, and is called from nowhere: grep returns its definition and docstring only.
- `overlay_element_marks` (`openadapt_ml/grounding/detector.py:433-561`), which draws numbered set-of-marks circles on the screenshot with PIL, is called only from `examples/test_gemini_grounding.py:67` and asserted non-None in `tests/test_gemini_grounding_imports.py:38`. - `encode_image_with_detail` (`openadapt_ml/models/providers/openai.py:214-240`), the only resolution hint control on an API path, is defined and never called.
