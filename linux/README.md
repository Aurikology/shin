# Pexi on a Linux VPS (OVHcloud VPS-2, Beauharnois, Ubuntu 24.04 LTS)

The Linux twin of `mac/`. Decision and checklist: `notes/launch-readiness-2026-11-26/server-decision.md` (section 7).
The move itself, command by command: `CUTOVER.md`. Nothing here has been run on a real Ubuntu box (the server does
not exist yet); every script has `bash -n`/`node --check` and tests for the logic that does not need systemd.
`shellcheck` is not installed on the PC where this was written, so it has NOT been run: run
`shellcheck linux/*.sh` once on the new box (`sudo apt-get install shellcheck`) before the first real run.

## Layout on the box

| Path | What |
|---|---|
| `/opt/pexi/live` | the clone the server runs from (twin of `~/shin-live`); never edited by hand |
| `/opt/pexi/stage` | where a commit is installed and tested first (twin of `~/shin-stage`) |
| `/opt/pexi/state` | deploy state: `last-good`, `previous`, `failed.json`, `HOLD`, `runs/` |
| `/var/lib/pexi` | live data (twin of `~/shin-data`): the databases, catalogue, photos, `health/`, `backup/`, `inbox/` |
| `/etc/pexi/pexi.env` | the one environment file, mode 0600, owner `pexi` (template: `pexi.env.example`) |
| `/etc/cloudflared/` | tunnel `config.yml` and the tunnel's credentials JSON |

Everything runs as the `pexi` user (no login shell, no sudo except one line: restart `pexi-server.service`).

## launchd -> systemd

The mac scripts (`mac/07-backup.sh`, `14-offsite-backup.sh`, `15-restore-test.sh`, `hammer-refresh.sh`,
`kroger-refresh.sh`, `openprices-refresh.sh`, `bcldb-refresh.sh`, `run-job.sh`, `lib/health.*`) are POSIX and use no macOS-only command, so the
units run them unchanged from `/opt/pexi/live/mac/` with `/etc/pexi/pexi.env` as their config. Times are local
(America/Toronto), as on the Mac. Unit files are generated by `make-units.mjs` (table inside) except the four marked *hand*.

| launchd label (`mac/launchd-daemons`) | systemd unit | When | Notes |
|---|---|---|---|
| `com.shin.server` | `pexi-server.service` (*hand*) | always, `Restart=always` | `TimeoutStopSec=30` for the 12 s drain; `EnvironmentFile=/etc/pexi/pexi.env`; `OOMScoreAdjust=-500`; crash alert via `ExecStopPost` |
| `com.shin.tunnel` (cloudflared service) | `pexi-tunnel.service` (*hand*) | always, enabled only at cutover | same tunnel UUID and hostname as the Mac |

What does not move: the Mac's non-repo health mail (`~/bin/worker-heartbeat.sh`) and the PC-Mac mailbox. They report on the Mac only.

## Alerts that leave the box (no SMTP, no server of ours)

One sender, `alert.mjs`, over HTTPS to **Healthchecks.io** (already in use: `scripts/deadman-probe.mjs`, free tier, it emails).
With one project ping key (`SHIN_HC_PING_KEY`) each job gets its own check, created on first use: a failure POSTs to
`https://hc-ping.com/<key>/pexi-<job>/fail?create=1` with the detail as the body, so Healthchecks emails once per failure
streak and mails again only after the job has recovered (`ok` ping). Optional second route: `SHIN_ALERT_URL` (any HTTPS
endpoint that accepts a POST, e.g. an ntfy.sh topic). Three triggers feed it: a job that exits non-zero (`OnFailure=`),
a job that records `FAILED` through `mac/lib/health.mjs` (which now calls the sender), and a server crash (`ExecStopPost`).
If no route is configured it exits non-zero and says so in the journal, never silently. Prove it works:
`node linux/alert.mjs test` (sends a fail then an ok; check the email arrives).
UNVERIFIED: that a check created by `?create=1` gets the project's email integration; `test` is how to find out.

## Outside uptime check (independent of the box)

`.github/workflows/uptime-5min.yml`: GitHub's own machines call `https://relay.anjiawenda.com/api/health` every 5 minutes
and fail the run (GitHub emails the account) when it is not a 200 with `ok: true`, three tries 20 s apart. GitHub may
delay a schedule under load (it did, 2026-11-18: readiness R02), so it is one layer of three, with the box's dead-man ping
(every 60 s, box to Healthchecks) and the existing `server-alarm.yml` (every 30 min, full phone-route probe).
For a second independent clock, add the same URL to a free UptimeRobot monitor (5 min).

## Secrets

`pexi.env.example` lists every variable the server and jobs read, generated from `settings/src/index.ts`
(`node linux/make-env-example.mjs --check` fails when it is stale). Each secret's comment says where its value comes from;
almost all are copied from the Mac's `mac/config.env`. `SHIN_NETWORK_SALT` must be copied, never regenerated.
